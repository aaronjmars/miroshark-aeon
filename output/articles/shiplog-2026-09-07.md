# Shiplog — Aug 31 → Sep 7

**By the numbers:** 272 PRs opened, 264 merged, across 34 repos (operator-wide GitHub search, not a sample). MiroShark/MiroShark — the public flagship — merged **3 PRs, all dependency bumps, 0 engine code.** MiroShark stars: **1,448 (+2)**. Forks: **298 (−1)**.

## The real finding: the public engine looks idle. It isn't.

`MiroShark/MiroShark` merged exactly 3 PRs this window:
- #297 `fix(deps): bump mistune to 3.3.3` (dependabot security alert)
- #296 `chore: bump transformers 5.5.0 → 5.10.1`
- #295 `chore: bump tornado 6.5.7 → 6.5.8`

Zero engine-code PRs. That's the **4th consecutive shiplog window** with nothing but dependency churn in the public repo (the 3rd was flagged in the 08-31 shiplog; nothing changed since). If you only watch the OSS repo — which is the one doing the star-collecting — the "$1 to simulate anything" engine has looked frozen for a month.

It isn't. The actual simulation work moved into the private companion repo, `MiroShark-x402`, which merged **43 PRs** this window — real engine changes, not chores:
- `perf(cache): revive prompt caching — widen gate to Gemini, un-nitro DeepSeek sim`
- `perf(sim): cap agent output, dedupe topic/summary work, tighten timeouts`
- `perf(report): cap ReAct iterations, keep grounded drafts, trim observation history`
- `feat(sim): attribute+reduce invalid actions, add real report citations`
- `fix(storage): make Neo4jStorage boot-resilient to a cold/paused Neo4j`
- `fix(sim): make trace inserts idempotent to stop UNIQUE-collision invalids`
- `cleanup(x402): drop ERC-7710 sidecar + dead code, add 3 prod-path sim fixes`

The public website (`miroshark-website`, private but Miroshark-branded) added another **22 merged PRs** — lighthouse/perf work, a use-case gallery + scenario picker, wallet UI, and folding the old x402 section into x402aff.

So the honest read: the engine is being worked hard, just not where the "0 engine-code PRs" headline metric looks. Whether that's a deliberate build-in-private-then-open-source-later call, or drift that's quietly starving the OSS repo of the commits that make it look alive to a stranger scrolling GitHub — that's a call for the operator, not something to guess at here. Either way, three-plus weeks of a stagnant-looking public repo is a real cost against the north-star (stars, forks, "ecosystem growth" all read off the public repo).
