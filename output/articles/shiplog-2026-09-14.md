# Shiplog — Sep 7 → Sep 14

**By the numbers (operator-wide, for scale):** 190 PRs opened, 186 merged, across 17 repos. **MiroShark-tagged repos merged 53 PRs this window** across the public engine + three private companions. MiroShark stars: **1,449 (+1)**. Forks: **299 (+1, recovering last week's first-ever dip)**.

## The ship: you can now export a MiroShark run as a video

`MiroShark-x402` (private) shipped the "Generate video" button on the report share page (#191), plus the polish batch that had to land first to make it worth shipping — interactive market/graph, count-up stats, copy-report, belief-hover, mobile fixes (#182–190). `miroshark-website` added the matching `miroshark-video` agent skill. Both `@aaronjmars` and `@miroshark_` announced it the same day (09-10): *"Generate simulation videos in one click on @miroshark_ 🦈 ... export the simulation in one click as a video 📽️"* ([tweet](https://x.com/miroshark_/status/2098066368880902493)).

Same repo also added **Monad as a 3rd x402 payment network** (#198) and a batch of sim-reliability fixes: reject non-object LLM JSON in the sim-config retry wrapper (#197), a forced `web_search` server-tool path behind a flag (#194/195), sim-scoped conditional tool_choice in wonderwall (#193), sell-guard + persona-name diversity + report-section-distinctness tuning (#182), and a dead-code/shared-types cleanup pass (#196). 17 merged PRs total — this is where the actual engine work landed this window, same pattern as last week.

## The public engine repo: still quiet, but not zero this time

`MiroShark/MiroShark` merged exactly 3 PRs:
- #301 `fix(i18n): thread locale through graph_builder ThreadPoolExecutor` — **AmirF194**, a contributor not seen in this tracker before. Worth noting: the PR description says *"same bug as #194/#195"* — this is the third time a ContextVar-based locale has failed to cross a `ThreadPoolExecutor` boundary in this codebase (first caught in `_fallback_interview` back in June, now in `graph_builder`'s `add_text_batches`). A recurring class of bug, caught again by an outside contributor.
- #299 / #298 — dependabot bumps (`pywebpush`, `vue-router`).

So: not the "0 engine code, 4 weeks straight" headline from last week — one real external fix landed. But it's still 1 substantive PR in the repo that collects the stars, against 17 in the repo that doesn't.

## x402aff: an actual outside integrator, not a metric

`@thecultos` integrated the x402aff standard this window — MiroShark simulations are now listed in Cult OS's x402 catalog, discoverable and payable in USDC on Base via MCP. Both accounts posted it: `@aaronjmars` framed it as *"building rails for a more exciting internet"* ([tweet](https://x.com/aaronjmars/status/2098519061910937623), 09-11), `@miroshark_` posted *"Projects are starting to adopt our x402aff standard!"* ([tweet](https://x.com/miroshark_/status/2098636629560774908), 09-12). Today's token-report (09-14) confirms this is still the dominant social topic, not price talk.

This is the first named third-party product integration of x402aff surfaced in this tracker — the affiliate-standard bet (launched 08-28) starting to pay off with a real adopter, not just an announcement.

One loose end from last week resolved the wrong way: [`x402-foundation/x402#3390`](https://github.com/x402-foundation/x402/pull/3390) (the PR to get x402aff listed in the x402 foundation's own docs) is now **closed, unmerged**. No external-org security merge to flex this window either — nothing in this window's operator PR list touches a repo the operator doesn't already control.

## Quietly maturing: the credibility machinery

`miroshark-bench` (private) merged 5 PRs this window: a judge panel, a 4-axis ranked scorecard, a model switch-decision system, `agent_action` tool_choice/cap/provider knobs, and a full 401-row panel-run dataset from 09-07. This is the infrastructure behind "prove a sim is worth trusting" — no public output yet, but the scoring rig is getting real.

`miroshark-website` also shipped a batch of "agent-readiness" plumbing this window: a spec-valid `/.well-known/ard.json` manifest, `trustManifest` on every ARD entry, `urn:air` identifier migration, plus a run of a11y/LCP/bundle-perf tier fixes and an SEO fix that unblocked share OG tags. Site-infra work, not stars-facing, but it's the kind of thing that determines whether an AI agent crawling the site can actually parse what MiroShark is.
